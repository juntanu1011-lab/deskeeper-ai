## アプリアイコン（確定）

`app-icon-1024.png` が確定版。App Store 提出仕様（1024×1024・PNG・**角丸なし**・透過なし）。
`icons/` に各サイズを書き出し済み。

生成の元は ChatGPT 出力の `app-icon-source-1254.jpg`。そこに以下の機械的な補正をかけている
（キャラクターの絵そのものは1ピクセルも描き替えていない）:

1. **背景の切り抜き** — 縁から塗りつぶし判定。判定条件は
   `輝度 < 26 かつ (R − B) < 4`。
   ⚠️ **輝度だけで判定してはいけない**。耳の暗い茶色は `#2E2013`（輝度34）で背景より明るいが、
   耳の内側の陰は `#180F06`（輝度16）と背景並みに暗い。**背景が青寄り（R−B ≈ −9）なのに対し
   毛は暖色（R−B ≈ +18〜+29）**という差だけが唯一の安全な判別軸。
   最初これを輝度のみで判定して**両耳が消えた**。
2. **背景の差し替え** — フラットな `#0A0C10` ではなく、以下の3層:
   - 縦グラデ `#12151D` → `#06070A`（暗い壁紙でアイコンの輪郭を立てるため）
   - 双眼鏡のレンズ位置（x=0.355 / 0.645、y=0.755）から琥珀 `#FFB02E` の放射光 26%
     — design.md の `glow.hero` をアイコンに持ち込んだもの。「レンズが光を漏らしている」表現
   - 琥珀のドットグリッド（間隔 0.075W・半径 0.11×間隔・不透明度16%）。
     **中央から半径0.35W以内はドットを消す**（顔とレンズを最優先で残すため）
3. 1254px → 1024px にリサンプル

1. 元PNGを 5px メディアンフィルタで JPEG ノイズ除去
2. ブランド5色に最近傍でスナップ（`#EDE0C8` / `#C9A574` / `#3D2C22` / `#1A1512` / `#FFFFFF`）
   — design.md §6 のトークン値に戻す工程を兼ねる
3. 3x3 モードフィルタで再度despeckle → 2倍に nearest 拡大（トレーサに輪郭サンプルを与える）
   → `peek_flat.png`
4. `imagetracerjs` にこの5色をパレット固定で渡し、粗さを4段階でトレース

## 検証結果

- **80px以下**（ヘッダー30px / favicon / SNSアイコン）では `d_min` と元PNGの差は目視で判別不能。
  ファイルは 231 KB → 14 KB、かつ解像度非依存。ここは今すぐ置き換えてよい。
- **300px以上**では全案とも輪郭に細かい波打ちが出る（自動トレース特有）。
  特に耳の外周と頭頂部。ヒーローや印刷にはこのままでは使えない。

## 【2026-08-04 追記】背景切り抜きの破損と切り直し

`peek-master.png` は、上記の切り抜きルール（`輝度 < 26 かつ (R − B) < 4`）で
**絵そのものに穴が開いていた**。

- **K を掴む手** — 大半が alpha=0 で欠落。手の色は `rgb(57,43,25)`
- **両耳の輪郭** — 縁が数か所えぐれていた

輝度と色相の閾値では、暗い毛（手 maxch 57・耳の内側の陰 maxch 24）と
ほぼ黒の地を安全に分けられない。**分けられるのは連結性だけ** — 地はキャンバス端から
到達できる1つの領域で、壊された画素はすべて絵に囲まれて外から到達できない。

`recut_peek.py` がこれをやり直している:

1. 端からのフラッドフィルで地を確定（`maxch <= 12` のみ、かつ端から連結）
2. 地に接していない暗い画素は**触らない**（耳の内側の陰が生き残る理由）
3. 地に接する画素だけ黒からアンプリマルチプライしてアンチエイリアスを復元
   （`a = maxch / maxch(最近傍の確定画素)`）

幾何は完全に保持。`peek-master.png` は原画を `(227,106)` から 549×920 で等倍に
切り出したものであることを画素差0で確認済みで、同じ窓を書き戻している
（`Wordmark.tsx` の `PEEK_AR` / `PEEK_CUT` が依存しているため）。

`web/public/mascot/mascot-peek.png`（286×480）と `lp-lockup/` の全ファイルも再生成した。
